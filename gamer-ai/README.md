# AI 助手

`gamer-ai` 是通用 builtin 插件，提供持续对话、配置包记忆、模型 API 游玩和本机 Streamable HTTP MCP。内置 Agent 与外部客户端共用受限记忆、网页、截图和输入工具。Android 与浏览器目标复用宿主能力，没有固定游戏脚本。版本为 `0.3.10`，需要 Gamer `0.2.14` 或更高版本中包含本次对话与记忆实现的宿主；只更新 UI 归档不能更新宿主执行能力。

## 对话与记忆

工作台默认进入“对话”，聊天与游玩共用输入框和时间线。选择配置包后即可讨论、整理攻略、指示 AI 管理记忆，不需要连接设备；描述实际操作目标时，Agent 根据消息自行调用游玩工具，使用工作台当前选定的设备，不需要切换消息模式。模型及外部 MCP 连接收在设置中，可选向量和联网服务在独立“可选服务”页配置。

用户消息显示已接收、待处理、已纳入与已撤回阶段；待处理消息可撤回，已纳入消息需要发新指令纠正。AI 答复按安全 Markdown 排版，公开思考独立显示且默认展开，工具操作以紧凑行呈现、参数和结果按需展开。缺少公开思考时显示真实状态，不编造内容；已完成的工具组折叠不会隐藏思考或最终答复。文本增量更新同一消息，最终收据中的完整文本为准，工具参数未完整校验不会进入设备操作。

每条消息先由模型根据真实用户文本与可信设备、配置包和会话状态判断需要问答还是操作。这一步不包含检索资料，资料不能授权开始或恢复设备。模型需要操作时，宿主才建立合法的游戏运行和输入租约；未选择设备时仍可问答，需要操作才提示选择。游戏运行中的截图和输入继续使用与 MCP 相同的执行器，不需要连接自身 HTTP MCP；HTTP MCP 入口供外部客户端使用。语义判断请求、实际工具和游戏进度均显示在同一对话中。

顶部“提示词”可编辑对话、游玩、后台记忆整理三份基础系统提示词，账号级私密保存，各最多 32 KiB UTF-8 字节。保存后从下一次实际模型请求生效，已有对话也会刷新；正在进行的请求和历史快照保留原值。“恢复默认”先填回表单，点击保存才生效。提示词版本独立于模型和可选服务连接，不改变已保存凭据。设备权限、暂停规则、当前包/设备/代次和记忆提交约束由运行时另行注入，不能靠编辑提示词授予权限。

每轮用户消息前显示“模型请求上下文”：在 HTTP 发送前记录最终协议请求体，保留 system/developer、历史、用户消息、检索资料、图片元数据的实际顺序，以及完整工具定义和请求参数。记忆资料也可能位于用户消息之后，不会重排成虚假的前置内容；后续工具循环的请求可分别展开。密钥、输入工具中的文本、图片像素和私密推理载荷脱敏，不记录认证请求头。旧轮次没有保存完整请求时会明确提示无法还原。后台整理作业也有独立、可分页的请求查看入口，相关游玩作业同时显示在对话中；请求快照不成为自动攻略总结材料。

对话按游标增量加载，可“加载更早记录”。阅读旧内容时保留滚动位置，点击“回到最新”再跟随新进度。公开历史与诊断保存在 Gamer 所在电脑的插件私有数据中，刷新或重启后可回看；回看不调用模型、不恢复输入租约、不重放动作。游玩开始时原地关联设备会话，保留之前讨论的历史；游戏截图、工具回执、暂停原因和后续讨论在主聊天可见。

外部 MCP 日志以及已删除配置包的旧对话只供回看，发送框会禁用并提示建立新对话；重建相同 Package ID 不会把旧记录自动恢复为可执行对话。

“取消本轮问答”只取消聊天处理；设备自动化使用单独的“暂停 AI 游玩”“明确继续 AI 游玩”“停止设备会话”。运行中收到新消息，先让当前动作安全收尾，再由 Agent 判断后续；查攻略或改记忆会保持暂停。已暂停时只有用户明确要求继续游戏，或点击顶部继续按钮，才会恢复；服务端仍须回收人工输入、递增代次并重新观察画面。

“聊天预算”与“游玩预算”分别显示各自累计用量，五项均支持 `0` 表示无限。调整聊天上限随下一条消息在安全边界生效；调整游玩上限保存为待用配置，在开始或明确继续时应用，修改不会自动恢复设备。实际游玩账本仍显示已生效的上限与用量。供应商配额和请求超时独立于运行预算。

### 只读记忆库

记忆归当前配置包所有，正文与修订保存在 `plugins/gamer-ai/memories/` 与 `memory-revisions/`，随 `.gamerpkg` 导出；本机 SQLite 混合检索索引是可重建缓存，不是正文权威来源。记忆库可检索、读全文、查看来源、适用条件、验证状态、人工保护字段和修订差异。选中条目可按具体 `id/revision` 附到对话，后续切包会清除界面的待附引用；已建立会话的记忆域保持冻结。

列表使用单栏卡片，标题与摘要各最多两行；点击进入完整阅读，返回时保留搜索、分页和位置。正文按安全 Markdown 展示，来源、修订历史、导入整理任务和索引按需展开。待整理原始经历会明确标注，不当作整理后的攻略。

界面不提供记忆正文编辑或状态修改按钮。新增、修改、停用、删除与恢复通过对话或独立授权的 MCP 指示 AI 完成。当前用户定义优先，人工保护内容需要明确委托；AI 写入使用内容版本和持久操作收据，冲突时重新读取，不能覆盖新版本。待验证经验不冒充已验证流程，来源环境已验证也不代表当前游戏环境已验证。旧坐标、设备代次、密钥及账号原文不作为长期攻略保存。

用户明确说“记住”或给出定义时，系统会在预算允许时保留受保护的原文；用户提供的经验或资料会自动暂存为来源，进入后台合并作业。AI 按需记录经过验证的步骤和踩坑，并保留环境、条件与来源；不会把整段对话、推测或失败尝试当成成功攻略。自动记忆同样受预算、验证状态和保护字段约束，处理进度与失败可在作业或诊断中查看。

AI 在写入或修订攻略前先查重并整理表达：标题概括主题，正文按需列出适用条件、操作步骤、成功判断和注意事项。修正错误后正文保留当前准确结论，旧错误、改动原因和调用过程放在来源与修订历史中；不删必要限制、不推定未知版本或验证状态。整理使用已有正常模型请求，不额外调用一个润色模型。受保护的用户原文和原始经历草稿仍保留，不能为了简短擅自改写。

游玩中的目标、补充指引和纠错无需包含“记住”才会记录。系统按持久对话保存安全原稿，每 10 次输入或约 60 秒更新同一条待复核过程草稿，暂停和结束也会补归档；流式输出再多也不会挤掉早期步骤。后台在前台空闲或游玩暂停时用 AI 提炼、合并。草稿、入队、处理进度、完成及错误直接显示在对话。重启会补归档尚未处理的旧游玩记录，不恢复设备控制；已删除的草稿和受保护定义不会被自动复建。过程草稿是待复核资料，不自动当成已验证攻略使用。

前台游玩优先推进当前用户目标，一般纠错直接用于当前决策，不必先写记忆才能继续。只有当前仍未完成的真实用户任务明确要求先查询或修复记忆，才作为操作前置任务；历史已经成功完成的修复不因旧记录或汇总再次成为前置，不反复核对或重做。其他经验在不妨碍目标的自然安全阶段按需整理，用户要求结算后再整理时遵守该顺序。工具调用次数不触发强制查重或写入，自动原稿归档仍持续进行。

记忆库搜索包含待验证草稿；模型常规检索优先经过验证、适用条件匹配的条目。资料来源后来被修订或删除时，卡片与全文显示“资料需复核”、引用修订与当前修订，并优先展示当前有效验证状态；保存的验证标记和保护正文保留。如果其他独立来源仍支持内容，有效状态可保持已验证，来源变更警告仍保留。读取来源时会注明显示的是旧引用原文，可在对话中委托 AI 复核。标题、词项与语义检索在本机融合，未配置 embedding 或向量暂不可用时显示降级原因，关键词支路继续可用，不把整库塞进模型。

普通对话每条新消息自动检索最多 5 个相关片段，仅用于本轮各次工具请求，不再逐轮累积到持久历史。保护定义独立保留：最多读取 8 条正文，必要字段合计不超过 24 KiB；目录最多 30 条且不超过 8 KiB，超出时提供按需读取提示。完整来源、更多定义及用户选择的原文使用记忆工具读取；真实用户消息、工具回执和已有历史快照仍保留。游玩在启动或恢复时检索，后台合并按当前原稿片段找候选；本机索引维护扫描不等于把全库发给模型。

### 导入与索引

在记忆库选择 MD/TXT 攻略，每个文件最多 1 MiB。文件先暂存为持久作业，AI 查询本包相关记忆后新增、补充、修订、合并或保留条件分支。现有正文保留，人工定义不会因导入被静默覆盖；模型暂不可用时保持待合并，不假报处理完成。

作业显示真实处理数及新增、修订、合并、保留、失败数量，可暂停、继续或取消。后台合并也有完整五项预算，均可填 `0` 表示无限；作业用量独立累计。暂停后可以调整上限并“按预算继续合并”，原有用量不会清零。已接收的文件与已提交的记忆使用稳定收据去重；失败后重试继续未完成部分。索引损坏或过期可重建，关键词重建不请求模型；补齐向量可能使用独立 embedding 额度。服务端保留来源原文与修订，可在只读来源视图回看。

### 可选服务与诊断

聊天 API、embedding API、搜索 API 分别配置、分别持有密钥、分别统计实际可得用量。向量支持 OpenAI Embeddings 兼容协议和 Cloudflare Workers AI；Cloudflare 可填 Account ID、独立 Token 与模型 `@cf/baai/bge-m3`。联网支持 Tavily、Brave、自建 SearXNG 与兼容服务；网页读取独立启用，默认阻止本机和私网地址。所有可选服务默认关闭，保存配置不发起模型或搜索请求，不自动开通付费服务或切换供应商。未配置服务时显示不可用，不隐式使用模型收费搜索。

向量和搜索都可选择自定义兼容供应商，按其接口选协议并填写独立密钥。完整接口地址 `endpoint` 优先于基础地址 `base_url`；留空时插件按所选协议拼接请求路径。服务商标签不触发自动切换或收费兜底，也不会借用聊天或另一服务的密钥。密钥留空仅保留当前连接已有的密钥，“清除密钥”需显式选择。

Embedding 的单次编码字节上限包含标题与编码前缀，默认 `480`，可填 `128–24576`，用作模型 Token 边界的保守约束。文档和查询前缀分别可选，各最多 256 个 UTF-8 字节且须小于编码上限；按供应商模型要求填写。编码上限、前缀或模型变化会改变向量指纹，需要在记忆库重建语义索引，关键词检索仍可使用。同一端点调整这些编码参数不更换密钥。

主聊天“诊断”提供模型请求、工具、记忆、状态和错误过滤，并可定位对应对话轮次。导出获取一致的脱敏快照后保存到本机，不调用模型、不上传日志。API key、Bearer、Cookie与私有推理不进入导出；真实 Token 数、预算和操作关联保留，缺失耗时、用量或附件显示未知。网页命中仅是外部资料，模型使用与保存来源仍遵守供应商留存规则。

## 内置 AI 使用

1. 安装并启用插件，在工作台选择设备和配置包。Android 应用目标来自设备的“应用”配置；浏览器目标需先连接并绑定画面。应用与配置包是两个独立上下文。
2. 在“模型连接”填写 API 基础地址、模型与密钥，点击“保存并测试连接”。默认模型为 `glm-5.3-flash`，默认协议为 Responses。基础地址不要加 `/responses` 或 `/chat/completions`，插件按所选协议拼接路径。
3. 测试结果中的模型连接、图片识别、基于图片的工具调用、工具截图反馈和工具结果回传都通过后，在底部输入框描述任务、成功条件与操作限制，发送开始对话。
4. 在同一输入框直接输入目标，例如“打开游戏设置”；需要时通过“预算”调整独立的对话和游玩上限。Agent 自动决定调用记忆还是游玩工具。对话时间线显示你的消息、AI 公开思考与回答、实际请求进度、截图及工具操作；展开工具行查看参数与结果。操作成功表示输入已注入，实际效果通过随后截图判断。
5. 随时在输入框补充要求或纠正方向。运行中收到消息会先让当前动作安全收尾；新的操作引导由 Agent 纳入并继续，问答和记忆修改保持暂停。原本已暂停的游戏，需明确说“继续刚才的游玩”，或点击顶部继续按钮。原始任务和后续指令保留在同一对话中。
6. 需要人工操作时点击“暂停 AI”，等待状态变为“已暂停”且投屏提示允许人工操作，再点击、按键或输入文字。完成后点击“继续 AI”；服务端重新取得控制权、递增 `generation` 并观察新画面。
7. 结束时点击“停止会话”。关闭面板或管理页面不会停止服务端会话。

建议先用可随时退出、无需高速反应的场景，目标可写为：“观察当前界面，找到设置入口并打开；成功条件是设置页可见；只使用必要操作，无法确认时停止说明原因。”用户自行选择游戏验证模型延迟、定位偏差及任务完成情况。

### 模型连接与真实验证

| 协议 | 基础地址 | 请求路径 |
| --- | --- | --- |
| Responses（默认） | `https://open.bigmodel.cn/api/v1` | `/responses` |
| Chat Completions | `https://open.bigmodel.cn/api/paas/v4` | `/chat/completions` |

2026-10-02 使用实际测试账户与 `glm-5.3-flash` 验证了两种协议：每种协议 4 次请求、5 个能力检查全部通过；合计 8 次请求、供应商回报 2421 tokens。测试包含连接标记、随机合成 PNG 的主色识别、依据图片生成带随机标记的函数调用，以及工具回传另一张图片后的继续识别。这是模型协议验证，不代表特定游戏已通过验收。

连接测试使用非游戏图片与无设备副作用的测试工具，不操作当前设备。若测试不通过，界面展示具体检查结果。可以显式选择 Chat Completions，再点击“填入此地址”、保存并重新测试；插件不会在游玩中静默切换地址或协议。保存配置不会更改已运行代次的连接，下一次开始或恢复使用已保存配置。

API 密钥只保存在宿主 `extension-data/gamer-ai/private/` 私密配置中。公共响应仅返回 `has_key`，密钥输入留空沿用已保存值，输入新值可更新；密钥不进入源码、日志或 Package 导出。发送给模型的内容包括用户目标、必要历史、目标截图和工具结果。每次更换配置后重新测试。

默认展示供应商公开提供的思考。智谱官方 `https://open.bigmodel.cn/api/v1` 的 GLM Responses 支持公开 `reasoning_text`，Chat Completions 支持公开 `reasoning_content`；其他 Responses 接口仅显示明确的公开 `summary_text`，不能据相同字段名推断其推理可公开。这些片段只用于对话展示，不进入设备工具执行历史，不读取或解密加密内容。旧历史中从未保存的思考无法补回。[智谱 Responses 返回结构](https://docs.bigmodel.cn/api-reference/response/创建-response)

模型的“单次输出上限”与会话累计 Token 预算独立，默认 `16384`，`0` 表示省略请求中的输出上限并采用供应商默认值。供应商仍可按模型能力限制输出；达到单轮限制时显示截断原因，尚未完整生成和校验的工具调用不会执行。会话累计预算 `0` 仍表示累计不限。

模型地址切换到其他 origin 时需重新提供该服务的密钥；同一 origin 下切换协议或路径可以保留。向量与搜索更换提供方、协议、端点或账号会清除各自旧密钥，需按新连接重新填写；仅更换 embedding 模型不会清除密钥。

### 控制权与预算

| 状态 | 人工输入 | 操作 |
| --- | --- | --- |
| 开始中、运行中、恢复中 | 锁定 | 可请求暂停或停止 |
| 暂停中 | 锁定 | 等待已入场动作结束、按键/触点释放 |
| 已暂停 | 允许 | 可人工操作，再继续或停止 |
| 停止中 | 清理完成前锁定 | 等待结束 |
| 已结束 | 允许 | 可开始新的会话 |

观看、音频设置及暂停/停止仍可使用，运行模型连接测试也不会阻塞会话暂停/停止。触控、键盘、粘贴、滚轮及应用启停受服务端仲裁，界面禁用只是提示；绕过界面直接调用人工输入接口也不能取得 AI 的控制权。工作台切换设备或配置包不会改写已开始会话的目标。浏览器重新绑定或 Android 应用配置改变时，需要停止旧会话后重新开始。

强制断开、删除设备或修改地址、屏幕模式、分辨率等投屏目标配置，必须先“停止会话”并等待结束，暂停不足以允许这些管理操作；服务端会拒绝操作，不会自动终止 AI。共享 ADB 强制重连还要求所有设备上的活动运行、采集、扩展及录制均已停止。普通“断开连接”只退出本页投屏，不会停止 AI。

默认预算：模型调用 40 次、工具 120 次、活动 600 秒、累计 100000 tokens、连续失败 3 次。**这五项预算均可填 `0` 表示该项无上限**，用量继续累计显示。模型调用按每次 API 请求累计，一条用户消息可能包含编排、查询及工具结果处理等多次请求，不等于一轮用户对话。非零范围分别为模型 1–500 次、工具 1–2000 次、活动 10–7200 秒、累计 2048–2000000 tokens、连续失败 1–20 次。截图和等待也计入工具次数。暂停保留同一运行槽和累计预算，暂停等待不计入活动时长；YAML、定时或其他自动化需要先停止 AI 会话才能取得该设备运行槽。

新建对话使用默认预算，不沿用当前历史对话的上限；未选中对话时主动编辑的预算用于随后建立的对话。历史对话的预算和累计用量保留。对话预算耗尽会显示中断原因与调整入口，提高上限或设为 `0` 后发送继续指令，修改预算不会自动重放原消息或开始设备操作。

任务在规划或查询阶段中断、尚未建立游戏会话时，新的“继续”消息也能引用同对话此前已纳入的真实用户目标和约束，重新规划并交接。编排只读取私密 inbox 中的真人原文，不把攻略、工具输出或模型回复当作用户授权；旧计划不会跨轮复用，实际操作仍按当前设备、运行代次和暂停屏障重新校验。

自动暂停会在对话时间线显示具体原因、实际用量或最后一次错误及下一步建议。预算耗尽时，可在已暂停的会话中提高对应上限，或将该项设为 `0`，再明确继续原对话；调整上限不清零累计用量。上限未提高时服务端拒绝恢复，避免刚继续就再次暂停。网络或工具失败后，继续会重新计算连续失败次数；失败上限为 `0` 时继续带退避重试，仍可随时暂停或停止。

供应商未提供部分请求 usage 时，会显示“至少 N（部分请求用量未知）”；其中 N 是所有已确认请求的累计用量，并作为预算检查下限。不会把未知用量当作零，也不会只显示“未知”而藏起已确认用量。

插件停用或服务端退出会收尾活动设备会话。持久对话可在重启后回看或继续普通聊天；设备游玩必须重新建立合法控制并观察，不能自动恢复 AI 或重放历史输入。界面仍保留兼容的当前会话快照，完整历史以持久对话为准。不提供持续视频推理、DOM/任意 JavaScript 工具、跨插件自动化或定时 AI 任务。

## 外部 MCP

### 连接与授权

在“外部 MCP”创建独立连接令牌。令牌固定授权一个设备及配置包，可选择“只读观察”或“允许控制”。外部 MCP 不要求配置模型 API 密钥。

设备绑定可以选择“不绑定设备”，仅授权本包记忆或联网工具。记忆读取、记忆维护、人工保护字段修改、独立联网默认不授予；旧令牌不会自动获得新增权限。记忆维护必须同时允许读取，勾选维护时界面自动补齐读取；取消读取会同时取消维护和保护字段修改。允许修改人工保护字段需要同时授予记忆维护。联网和设备控制不会随记忆维护自动勾选。记忆工具不要求设备输入租约，游戏暂停时仍可调用；它们不能恢复游戏。联网需要既有服务配置，令牌权限不代替供应商配置。

- **只读观察**：可以查询上下文及截屏，无需开始 AI 会话。调用 `screen_capture` 时不带 `session_id` 与 `generation`；返回 `generation: 0` 的观察画面，不能将它用于控制输入。
- **允许控制**：在设置的“外部 MCP”中输入目标并点击“建立外部控制会话”，再创建同设备、同配置包的控制令牌。客户端不能通过 MCP 开始、恢复、换目标或绕过用户暂停；外部客户端的后续指令在该客户端输入。

地址为 `/api/extensions/gamer-ai/mcp`。面板按当前页面地址生成示例；客户端必须运行在 Gamer 服务端所在电脑上，直连该服务端的回环地址和实际端口。例如默认端口为 `http://127.0.0.1:8443/api/extensions/gamer-ai/mcp`。管理页面经远程地址或 Vite 开发代理打开时，请改用服务端回环地址；代理带 `Forwarded` 或 `X-Forwarded-For` 会被拒绝。远程管理 Cookie、管理员 token 和非回环客户端均不能替代 MCP Bearer 令牌。

支持 `url` 与 `headers` 的标准客户端可配置：

```json
{
  "mcpServers": {
    "gamer": {
      "url": "http://127.0.0.1:8443/api/extensions/gamer-ai/mcp",
      "headers": { "Authorization": "Bearer <面板中创建的连接令牌>" }
    }
  }
}
```

客户端自动补充 MCP 标准请求头。手工发送 JSON-RPC POST 时必须包含：

```http
Authorization: Bearer <连接令牌>
Content-Type: application/json
Accept: application/json, text/event-stream
MCP-Protocol-Version: 2025-11-25
```

`MCP-Protocol-Version` 在初始化后使用服务端协商返回的版本，支持 `2025-03-26`、`2025-06-18`、`2025-11-25`。HTTP 客户端自动提供回环 `Host`；若提供 `Origin`，必须与 Host 匹配且为回环来源。传输采用无状态 Streamable HTTP POST：普通请求返回 JSON，通知返回 `202`；不发放或要求 `Mcp-Session-Id`，也无需维持 SSE 连接。

初始化请求示例：

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"my-game-client","version":"1.0"}}}
```

初始化后发送 `notifications/initialized` 通知，再通过 `tools/list` 获取当前令牌和目标能力对应的工具。完整令牌仅在创建响应中显示，列表不返回原文；丢失时创建新令牌并撤销旧令牌。

### 工具目录

下表为设备游玩工具，所有坐标使用返回截图的 `width`/`height`；服务端负责映射到原画面。完整目录按令牌作用域发现，目标不支持的工具不会出现在 `tools/list` 中；浏览器目标没有 Android 应用启停工具。

| 工具 | 主要参数 | 内容 |
| --- | --- | --- |
| `target_list` | 无 | 返回令牌授权目标和能力，不枚举其他设备 |
| `context_get` | 无 | 当前设备、运行目标身份及配置包 |
| `session_status` | 无 | 同配置包的当前会话、状态、`generation` 与输入控制状态 |
| `screen_capture` | `max_width?`；控制用图带 `session_id`、`generation` | 最新 PNG、`frame_id`、采集时间、截图与原画面尺寸；默认最大宽度 1280，可设 320–1920 |
| `input_tap` | `frame_id,x,y` | 点击后释放 |
| `input_press` | `frame_id,x,y,duration_ms` | 长按并释放，60–3000 毫秒 |
| `input_swipe` | `frame_id,x1,y1,x2,y2,duration_ms` | 滑动并释放，100–3000 毫秒 |
| `input_key` | `frame_id,key,duration_ms?` | 命名按键，如 `Enter`、`Escape`、`ArrowUp`、`KeyW`、`BACK`；按住不超过 3000 毫秒 |
| `input_text` | `frame_id,text` | 输入最多 2000 字符，事件日志隐藏正文 |
| `app_launch`、`app_stop` | `frame_id` | 启停设备已配置的 Android 应用，无任意包名参数 |
| `wait` | `duration_ms` | 可取消等待，1–5000 毫秒 |
| `session_finish` | `message` | 说明完成或无法继续并结束会话 |

除只读查询与 `screen_capture` 外，控制工具还必须带 `session_id`、`generation`、`operation_id`。`wait` 和 `session_finish` 也要求这些字段，但不要求 `frame_id`。截图返回标准 MCP `content` 的 image block 和文本元数据，同时提供 `structuredContent`，不是仅返回文件路径或 Base64 文本。

记忆工具包括 `memory_search/get/list/history`、受限新增/修订/停用/删除/恢复/合并、攻略来源与导入作业、索引查询等。它们按令牌冻结的配置包执行，不读取任意包。读取使用 `id/revision`；修改使用稳定 `operation_id` 和当前 `expected_version` 内容哈希，业务修订号不能替代并发票据。没有记忆写入权限时，`tools/list` 不提供修改工具。`web_search/web_read` 同样依令牌权限与可选服务状态提供。

### 一次控制的请求顺序

1. 调用 `session_status`，取得状态为 `running` 的 `session_id` 和当前 `generation`。会话为空或处于 `paused` 时，由用户在面板处理。
2. 带这两个字段调用 `screen_capture`，读出最新 `frame_id`、`width`、`height` 并观察图片。
3. 为新操作生成唯一 `operation_id`（建议 UUID，最多 128 字节），连同三个身份字段及所需参数调用输入工具。
4. 同一令牌、同一会话和代次内重试同一操作必须复用 `operation_id` 与完整原参数；服务端返回已记录结果，不重复注入。新操作必须用新 ID；相同 ID 修改工具或参数会被拒绝。JSON-RPC 的 `id` 只关联请求与响应，不能用来代替操作去重 ID。
5. 每次成功输入后重新截图，再决定下一步。暂停/恢复改变 `generation`，旧请求失效；画面身份、尺寸或目标连接改变时，旧 `frame_id` 失效。

调用示例（标识均替换为实际值，坐标须依据截图选取）：

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"session_status","arguments":{}}}
```

```json
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"screen_capture","arguments":{"session_id":"<会话ID>","generation":1,"max_width":1280}}}
```

```json
{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"input_tap","arguments":{"session_id":"<会话ID>","generation":1,"operation_id":"<本次操作UUID>","frame_id":"<最近截图ID>","x":100,"y":200}}}
```

工具错误通过 `result.isError: true` 和文本说明返回。收到 `stale_generation` 或 `stale_frame` 后先重新查询/观察，不更换去重 ID 盲目重复旧动作。若结果丢失，先以原参数和 ID 重试获取执行收据，再观察；客户端重启丢失这些标识时不能假设旧操作没有执行。

### 令牌与活动租约

令牌有效期固定 24 小时，可随时撤销。`ttl_seconds` 是控制会话的不活跃租约，不是令牌有效期：允许 30–3600 秒，默认 120 秒。有效的绑定会话工具请求或控制令牌的 MCP `ping` 可续租；只读查询、只读令牌及无效/过时代次操作不会取得控制权。客户端应以低于租约期限的间隔发送 `ping`。

建立或恢复外部会话后有初始 120 秒连接窗口；客户端第一次有效会话工具请求或 `ping` 后，按令牌的 `ttl_seconds` 续租，并以令牌的 24 小时到期时间为上限。测试短租约时，先发送一次有效请求，再停止续租并等待指定时长。`ping` 请求示例：

```json
{"jsonrpc":"2.0","id":5,"method":"ping"}
```

租约到期、控制令牌过期或撤销会暂停关联控制会话。重新连接或创建新令牌后仍需要用户点击“继续 AI”；续租不能解除人工暂停。HTTP 返回或连接关闭不等于客户端失联，离线后通过租约期限收回控制。停止会话会释放运行槽。

## 自测清单

- 保存模型配置并运行连接测试，确认五项通过、协议与地址符合选择；切换协议时重新测试。
- 内置模式开始简单目标，核对截图和记录；运行中尝试人工点击、按键、粘贴及应用启停，应被拒绝。
- 暂停时等待“已暂停”，人工点击应恢复；继续后 AI 使用新截图，旧代次/旧画面的外部请求应失败。停止后可运行其他自动化。
- 暂停时修改投屏参数或尝试强制断开，应被要求先停止；停止完成后才允许这些管理操作。运行连接 probe 期间仍可在主对话顶部暂停和停止会话。
- 创建只读令牌，不开始 AI 会话，完成初始化、工具列表和 `screen_capture`；确认没有输入工具。
- 建立外部 MCP 会话，创建控制令牌，通过上述顺序截图并执行一次操作。原 ID/参数重试不重复输入，原 ID 改参数被拒绝；操作后必须重新截图。
- 暂停外部会话后继续 `ping`，确认仍保持暂停；恢复后先 `ping` 一次，再停止续租并等待租约期限，应暂停。撤销控制令牌也应暂停，恢复必须由用户操作。
- 对 Android 与浏览器分别检查支持的工具；实际游戏完成率和延迟由用户选择游戏验证。

已通过插件 UI、构建、Rust 集成和真实 GLM 模型协议检查。隔离 Chrome 合成页面已贯通 MCP 截图/操作与内置模型循环，验证暂停恢复、旧请求拒绝、令牌撤销/到期、预算暂停和停止后立即关闭目标；内置循环使用本机 Responses fixture，实际 GLM 图像与工具协议另行实测。Android 输入使用真实回环 TCP 验证注入、断连和旧连接清理；实际 Android 设备与游戏效果按上述清单自测。

## 开发与构建

UI 使用 SDK v1 宿主模块以及 `WORKSPACE_CONTEXT_KEY` 只读快照，动态模块导出 `AiWorkspace`。设备、Android 应用、Package 与插件身份独立；业务代码不进入 Core 壳。

```powershell
# 主仓根目录：插件 UI 与宿主 UI 集成
node tools/check-plugin-sdk.mjs
node tools/build-plugin-ui.mjs gamer-ai
# 插件目录：单独验证 UI
cd plugins/gamer-ai/ui
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

插件仓根目录可运行 `./gamer-ai/build.ps1`，或 `./build.ps1 -Plugin gamer-ai`，输出 `dist/plugins/gamer-ai-0.3.10.gplugin`、目录和校验清单。主仓 `tools/build-plugins.ps1` 也能包装；开发时可显式指定输出目录以免覆盖本地市场目录。

执行体位于 `host/` 并编译进宿主，安装 UI 归档需要匹配的宿主版本。独立包装复用 `sdk/lock.json` 固定快照，无 WASM 占位文件，不依赖 gamer-yaml。修改 host 后必须一起构建/发布 Gamer 本体。
